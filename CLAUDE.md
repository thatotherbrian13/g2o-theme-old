## Build System

**npm scripts** handle all asset compilation via PostCSS and esbuild.

```bash
# Install dependencies (only needed once)
cd app/public/wp-content/themes/g2o && npm install

# Build commands
npm run build      # One-time build (CSS + JS)
npm run dev        # Build + watch for changes
npm run prod       # Production build (minified)

# Individual builds
npm run build:css  # Compile CSS only
npm run build:js   # Bundle JavaScript only
npm run build:nav  # Copy nav.js to build (standalone, not bundled)

# Watch individual file types
npm run watch:css  # Watch CSS changes
npm run watch:js   # Watch JS changes
npm run watch:nav  # Watch nav.js changes
npm run watch      # All three watchers (no initial build)
```

**PostCSS Pipeline** (postcss.config.js): postcss-import → postcss-calc → tailwindcss/nesting → tailwindcss → autoprefixer

**JavaScript Bundling** (esbuild.config.js): ES modules bundled with esbuild into single IIFE (`build/js/scripts.js`). Targets ES2020. Sourcemaps generated in development, minified in production.

**Never edit `/build/` files directly** - they are auto-generated from `/source/`. Note: `build/` IS tracked in git (not in `.gitignore`), so compiled assets must be committed alongside source changes. Always run a build before committing.

### wp-cli / Database Access (LocalWP)

`wp` is not on PATH, and `DB_HOST` in wp-config.php is `localhost`, which misses LocalWP's per-site MySQL socket. Use the bundled binaries with a socket override (LocalWP must be running):

```bash
PHP="$HOME/Library/Application Support/Local/lightning-services/php-8.2.29+0/bin/darwin-arm64/bin/php"
WPCLI="/Applications/Local.app/Contents/Resources/extraResources/bin/wp-cli/wp-cli.phar"
SOCK="$HOME/Library/Application Support/Local/run/baGT-EtbC/mysql/mysqld.sock"
"$PHP" "$WPCLI" --path="$HOME/Local Sites/g2o/app/public" \
  --exec="define('DB_HOST', 'localhost:$SOCK');" <command...>
```

This emits a harmless "Constant DB_HOST already defined" warning. Direct MySQL access: same socket, user `root`, password `root`, database `local`. Updating existing ACF values via `wp post meta update` is safe; **adding** flexible-content rows via DB requires the serialized layout list plus `_`-prefixed field-key companion rows — error-prone, prefer the WP admin editor for structural changes.

**Content gotchas when scripting changes:**
- **Yoast**: changing `_yoast_wpseo_*` meta or post status via wp-cli doesn't update the `wp_yoast_indexable` table, so the page keeps its old robots tag and sitemap entry. Rebuild with `YoastSEO()->classes->get(\Yoast\WP\SEO\Builders\Indexable_Builder::class)->build_for_id_and_type($id, 'post', $existing)->save()`, then curl the page for `<meta name='robots'>`.
- **Redirects** live in the Redirection plugin (`wp_redirection_items`, group 1, plain `url` match; create with `Red_Item::create()`). Renamed posts also get WordPress's own `_wp_old_slug` redirects, which can point retired URLs at the wrong page; delete the postmeta row to stop one.
- **Database pushes**: a Local push with the database replaces production's DB, including any Gravity Forms entries or job applications submitted since the last pull. Check those in production WP Admin first. Content fixes (redirects, Yoast, ACF) need the DB pushed; theme code needs only files.

## Theme Architecture

```
app/public/wp-content/themes/g2o/
├── functions.php                    # Theme setup, feature flags, asset enqueue
├── source/styles/main.css           # CSS entry point (imports all partials)
├── source/scripts/scripts.js        # JS entry point (ES module imports)
├── build/                           # Compiled output (auto-generated)
├── theme/inc/                       # PHP includes (walkers, ACF, utilities)
├── template-parts/stacks/           # 50+ reusable page components
└── template-parts/navigation/       # Navigation templates (site-nav.php)
```

### Key Patterns

**Stack Components**: Reusable page sections in `template-parts/stacks/stack-*.php` with matching CSS in `source/styles/stacks/stack-*.css`. Called via `get_template_part()`.

**Stack Contexts**: Different page types render stacks via dedicated files in `template-parts/`:
- `stacks-page.php` — Default page stacks (ACF flexible content)
- `stacks-post.php` — Single post stacks
- `stacks-header.php` / `stacks-home-header.php` — Page/homepage header stacks
- `stacks-footer.php` — Footer stacks
- `stacks-project.php` / `stacks-job_listing.php` — CPT-specific stacks

**Walker Classes**: Custom menu walkers in `theme/inc/walker-*.php` and `theme/inc/class-g2o-nav-walker*.php`.

**ACF Fields**: The main stack field groups are managed in the ACF admin UI and stored in the database — the stack layouts are seamless clones of "Component: *" field groups that show under ACF's **Inactive** filter (e.g. "Component: Banner"). Only the ChangeMakers fields are registered in PHP (`theme/inc/acf-changemakers-*.php`). In postmeta, stack sub-fields are stored with layout-prefixed keys (e.g. `header_stacks_0_banner_headline`, `page_stacks_0_author_body`).

**Button Rendering**: Use `g2o_render_button($button)` and `g2o_render_buttons($buttons)` from `theme/inc/acf-functions.php`. These produce FSE-compatible `wp-block-button` markup with style/color support.

**Asset Loading**: Uses `filemtime()` for cache busting in functions.php.

**Analytics events**: GTM container `GTM-PWCWDNTQ` (G2O-owned; replaced `GTM-T8H9RVD4` 2026-11) is hard-coded in `header.php` (`<head>` script + `<noscript>` after `<body>`). It holds the GA4 tag — add no `gtag`/GA code in the theme. `theme/inc/analytics-events.php` pushes one event, `g2o_conversion` (`conversion_type` lead/download/newsletter/job_application, `form_provider`, `form_id`, `form_name`, `page_path`), with no personal data. Form IDs/GUIDs map to type + name in `g2o_conversion_gravity_map()` / `g2o_conversion_hubspot_map()` — **add new forms there**. Gravity Forms push from `gform_confirmation` (success only; redirect-to-PDF confirmations become a message + push + JS redirect). Job applications set a cookie in the plugin's after-save hooks; a WPCode snippet ("Job Application Redirect") redirects to `/page-success-application/`, which reads the cookie and pushes. Each job listing's "Apply Now!" stack holds `[job_apply id="<its own ID>"]` — copy-pasted IDs file applications under the wrong job. The Gravity Forms Google Analytics add-on still pushes its own older events for forms 2, 6, 8, 9. To test submissions locally, block email (`pre_wp_mail`), strip captcha fields (keys only work on g2o.com), skip add-on feeds (`gform_addon_pre_process_feeds`, else HubSpot gets contacts), block GTM/GA requests, use a real-domain email (GF rejects `example.com`), and delete the test entries before any DB push.

**Custom Page Templates**: `template-changemakers.php` (conference page), `template-changemakers-survey.php` (conference survey), `page-brand-guide.php` (component catalog), `template-stack-guide.php` (stack showcase), `page-work.php` (portfolio).

**Stack Variants**: Some stacks support a `component_type` ACF field that switches between color/layout variants. The template uses `if/elseif/else` blocks — each variant renders the same layout structure with different color classes and an optional CSS class for custom backgrounds (e.g., dark gradients). The Stack Guide (`class-stack-guide-data.php`) lists supported variants per stack and renders each automatically.

| `banner` | default, `simple`, `wedge`, `form`, `gradient`, `boxed`, `download`, `solution` | `border_color` |

**Banner `download` variant — gated vs ungated**: renders a white-paper header (headline/deck/bullets left, cover image right). With `gravity_form_shortcode` (or `hubspot_form_shortcode`) set, the download is gated behind the form (e.g. `/what-is-the-ai-opportunity/`). With both form shortcodes empty, it renders the `link` field as a box button under the bullets and wraps the cover image in the same link — an ungated direct download (e.g. `/ai-ready-data-foundations-white-paper/`). Note: ACF conditional logic hides the Link field in the editor for the download variant ("Component: Banner" group); either remove the `Component Type != download` rule in ACF admin or set `header_stacks_N_banner_link` via wp-cli.

## Navigation System

### Feature Flags
```php
// functions.php
define('G2O_NEW_NAV', apply_filters('g2o_new_nav_enabled', true));
define('G2O_NAV_VERSION', apply_filters('g2o_nav_version', 'v1'));
```

### Version Switching
```php
// Method 1: Filter
add_filter('g2o_nav_version', function() { return 'v2'; });

// Method 2: wp-config.php
define('G2O_NAV_VERSION_OVERRIDE', 'v2');
```

### Navigation Files
| Component | Files |
|-----------|-------|
| Walkers | `theme/inc/class-g2o-nav-walker.php`, `class-g2o-nav-walker-v2.php` |
| Template | `template-parts/navigation/site-nav.php` |
| CSS | `build/css/nav.css` (manually maintained in `build/`, no source equivalent — edit directly) |
| JS | `build/js/nav.js` (copied directly from `source/scripts/nav.js`, not bundled) |

**Important**: `nav.js` is copied as-is to `build/` — it is NOT processed through esbuild. It must be written as vanilla browser-compatible JavaScript (no ES module `import`/`export` syntax, no Node APIs). All other scripts go through esbuild bundling via `source/scripts/scripts.js`.

### Navigation Behavior

**Desktop**: Hover-based dropdowns (160ms open delay, 120ms close). Parent items are `<button>`s (containers, not pages): click, Enter or Space toggles the dropdown; Escape closes it and returns focus to the button; Tabbing out of an open dropdown closes it. Arrow keys also move between items.

**Mobile**: Full-screen hamburger menu with accordion submenus. Click toggles open/close. Only one section open at a time.

**Accessibility**: Disclosure navigation pattern: plain `nav > ul > li` with `button[aria-expanded][aria-controls]` triggers. **Don't add `menubar`/`menu`/`menuitem` roles** (they failed axe `aria-required-children` sitewide; removed 2026-11). No roving tabindex: every link is in the Tab order. Focus is trapped in the mobile menu. Desktop buttons also carry `data-mobile-accordion`, so the accordion click handler must return early at desktop widths.

### State Management
- Dual tracking with both `aria-expanded` and `data-expanded` attributes
- CSS dropdowns controlled by JavaScript setting `aria-hidden`
- 200ms hover block after clicks prevents conflicts

## Stack Anchor Links

Stack IDs like `#stack-form-9` are auto-generated for deep linking to specific sections on a page.

### How IDs Are Generated

In `template-parts/stacks-page.php`, each stack gets an ID based on its layout type and position:

```php
$layout = get_row_layout('page_stacks');     // e.g., "stack_form"
$args_id = str_replace("_", "-", $layout);   // e.g., "stack-form"
$args = array(
    'id' => $args_id . '-' . get_row_index(), // e.g., "stack-form-9"
);
```

**The number is the stack's 1-indexed position on the page** (from ACF's `get_row_index()`).

### Finding/Predicting Stack Numbers

1. Open the page in WordPress editor
2. Count the stack's position in the "Page Stacks" flexible content field
3. The ID will be `stack-{type}-{position}`

### Custom IDs (Form Stacks)

Form stacks (`stack_form.php`) support a `unique_id` ACF field that overrides auto-generated IDs:

```php
$unique_id = get_sub_field('unique_id');
$id = ($unique_id) ? $unique_id : $stack_id;
```

**To use a custom ID:**
1. Edit the form stack in the page editor
2. Fill in the "Unique ID" field (e.g., `contact-form`)
3. Link to it as `#contact-form` instead of `#stack-form-9`

Custom IDs are stable and won't change when stacks are reordered.

### Stack ID Pattern

All stacks follow the pattern `#stack-{type}-{n}` where `{type}` is the layout name with underscores replaced by hyphens (e.g., `stack_gravity_form` → `#stack-gravity-form-{n}`).
